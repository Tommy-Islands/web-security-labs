## 2. 攻撃シナリオと背景

### 想定するシステム

商品カテゴリによる絞り込み機能を備えたECサイトを想定する。

このサイトでは、商品情報のほか、会員情報や注文情報などがデータベースに保存されている可能性がある。

商品一覧の取得には、URLパラメータ `category` が使用されている。

### 攻撃者の目的

攻撃者は、商品一覧の検索機能に存在するSQLインジェクションの脆弱性を悪用し、本来アクセスできないデータベース内の情報を取得することを狙う。

想定される標的には、以下がある。

- ユーザーの氏名やメールアドレスなどの個人情報
- 注文履歴や購入情報
- アプリケーションが管理する認証関連データ

※ 上記は一般的な攻撃シナリオとして想定した情報であり、今回のラボで取得したデータではない。

### 想定する攻撃の流れ

**第1段階：入力箇所の特定**

商品カテゴリの選択によって送信されるHTTPリクエストを調査し、`category` パラメータがSQLの処理に影響するか確認する。

**第2段階：取得列数の調査**

UNION攻撃を成立させるため、`UNION SELECT NULL` の列数を変更し、元のSELECT文と一致する列数を特定する。

今回のラボでは、3列を指定した場合に正常なレスポンスが得られた。

**第3段階：データ型と出力位置の調査（未実施）**

特定した列のうち、文字列などの情報を取得できる列や、検索結果が画面に表示される位置を調査する。

**第4段階：別テーブルの情報取得（未実施）**

列数やデータ型などの条件が揃い、データベースへのアクセス権限が許す場合、別テーブルの情報を取得できる可能性がある。

### 想定される被害

SQLインジェクションが悪用されると、アプリケーションの実装やデータベースの権限によっては、次の被害につながる可能性がある。

- 個人情報や機密情報の漏えい
- 非公開情報への不正アクセス
- データの改ざんや削除
- サービスの信用低下や事業上の損失

### 今回の検証範囲

今回実施したのは、第2段階の「UNION攻撃に必要な列数の特定」までである。

1列と2列ではHTTP 500、3列ではHTTP 200が返り、PortSwiggerのラボがSolvedとなった。

実際の個人情報の取得、別テーブルの参照、データ改ざんなどは実施していない。
